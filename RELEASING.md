# Как выпустить новую версию

Выпуски собираются в GitHub Actions из кода этого репозитория. У программы для ПК и приложения для Android они отдельные и со своими номерами версий:

| | Для ПК | Для Android |
|---|---|---|
| Запуск в **Actions** | **Выпуск** | **Выпуск Android** |
| Тег выпуска | `v1.2.3` | `android-v1.2.3` |
| Заголовок | «departament 1.2.3» | «departament для Android 1.2.3» |
| Файлы | установщик `departament-setup.exe`, архив обновления `departament-windows-x64.zip` и его контрольная сумма | APK `departament_<версия>_<процессор>.apk` для `arm64-v8a`, `armeabi-v7a`, `x86`, `x86_64` и `universal`, который подходит любому телефону |
| Описание | `release-notes/v1.2.3.md` | `release-notes/android-v1.2.3.md` |

Установленные программы проверяют страницу Releases и предлагают обновиться, как только там появляется опубликованный выпуск со своим тегом и номером больше, чем у них: программа для ПК — сама, приложение Android — в «Настройки» → «Проверить обновления». Выпуск для Android программу на ПК не трогает, и наоборот.

Номер версии пишется как `1.2.3`. Каждый следующий номер своей программы должен быть больше прошлого, иначе она обновление не увидит.

Отметка «Latest» на странице Releases всегда остаётся у выпуска для ПК: по ней программа для ПК находит свои обновления. После публикации выпуска для Android «Выпуск Android» сам возвращает её выпуску для ПК и переводит кнопку «Скачать для Android» в README на новый выпуск.

## Ключ подписи Android

Android ставит обновление, только если оно подписано тем же ключом, что и установленное приложение. Ключ лежит в секретах репозитория (**Settings** → **Secrets and variables** → **Actions**): `APP_KEYSTORE_BASE64`, `APP_KEYSTORE_PASSWORD`, `APP_KEYSTORE_ALIAS`, `APP_KEY_PASSWORD`. Без них выпуск для Android не собирается. Сам файл ключа храните отдельно в надёжном месте: если его потерять, новые версии не встанут поверх уже установленного приложения.

## Способ 1. Черновик от сборки

Так файлы готовы и проверены до того, как выпуск увидят люди.

1. Откройте вкладку **Actions**, слева выберите **Выпуск** (для ПК) или **Выпуск Android**, справа нажмите **Run workflow**.
2. Впишите номер версии, например `1.0.2`, и нажмите зелёную **Run workflow**.
3. Через 10–15 минут на странице **Releases** появится черновик: «departament 1.0.2» с файлами для ПК или «departament для Android 1.0.2» с APK.
4. Откройте черновик карандашом **Edit**, поправьте описание и нажмите **Publish release**.

Текст описания черновик берёт из файла `release-notes/v1.0.2.md` (для Android — `release-notes/android-v1.0.2.md`), если вы его заранее положили в репозиторий. Если файла нет, описание можно написать прямо в черновике.

## Способ 2. Сразу со страницы Releases

1. **Releases** → **Draft a new release**.
2. **Choose a tag** → впишите `v1.0.2` для ПК или `android-v1.0.2` для Android → **Create new tag … on publish**.
3. Заголовок, например «departament 1.0.2» или «departament для Android 1.0.2», и описание.
4. **Publish release**.

Файлы — установщик и архив обновления для ПК или APK для Android — сборка приложит к выпуску сама через 10–15 минут. Пока файлов нет, программы обновление не предлагают.

## Предварительный выпуск

Номер вида `1.1.0-rc.1` выходит как предварительный. Его получат только те, у кого на экране обновлений включён поиск предварительных выпусков.

## Если что-то пошло не так

- Сборка упала: откройте запуск во вкладке **Actions**, там видна причина. Исправьте её и запустите выпуск ещё раз с тем же номером, если черновика ещё нет.
- Черновик можно пересобрать: запустите «Выпуск» или «Выпуск Android» с тем же номером, и старый черновик заменится новым.
- Опубликованный выпуск не пересобирается и не подменяется: люди, возможно, уже скачали его файлы. Для исправления выпустите следующую версию.
- Описание вышедшего выпуска правится прямо на его странице карандашом **Edit**. Если поправили файл в `release-notes/`, запустите в Actions **Описание выпуска**, выберите ПК или Android и впишите номер версии, и текст на странице заменится.

## Что где лежит

- `departament/departament.Desktop` — программа.
- `departament/ServiceLib` — подключение, подписки, обновления.
- `departament/AmazTool` — помощник, который ставит обновление.
- `installer/departament.iss` — установщик.
- `android/` — приложение для Android. Туннель — подмодуль `android/hev-socks5-tunnel`, версию ядра Xray задаёт тег подмодуля `android/AndroidLibXrayLite`.
- `.github/workflows/build.yml` — сборка для ПК. Каждый пуш в `main` собирает программу, готовые файлы лежат в артефактах запуска. Здесь же закреплены версии ядер Xray и sing-box.
- `.github/workflows/android.yml` — сборка для Android. Пуш в `main` с правками в `android/` собирает тестовый APK: он лежит в артефактах запуска и ставится поверх выпуска.
- `.github/workflows/release.yml` — выпуск для ПК.
- `.github/workflows/release-android.yml` — выпуск для Android.
- `.github/workflows/notes.yml` — замена описания выпуска.
- `release-notes/` — описания выпусков.
